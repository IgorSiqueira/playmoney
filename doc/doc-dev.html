Motor de Odds
Como o sistema calcula a probabilidade de vitória de cada jogador e converte em odds. Inclui fórmulas exatas, valores base, tabela de ranks e exemplos numéricos passo-a-passo.

Visão Geral do Motor

Toda aposta começa pela função calculateDynamicOdds(matches, stats) em src/lib/odds.ts. Ela recebe as últimas 20 partidas (OpenDota) e o perfil estatístico do jogador, e retorna a probabilidade de vitória junto com todos os fatores intermediários.

O fluxo completo:

// src/app/api/bets/route.ts — POST /api/bets
const { stats, recentMatches } = await calculatePlayerStatsWithMatches(accountId);
const { winProbability } = calculateDynamicOdds(recentMatches, stats);  // → ex: 0.618
const { odds } = calculateComboOdds(winProbability, conditions, stats); // → ex: 1.48
const payout = calculatePayout(amount, odds);                         // → ex: 148.00

Os 6 Fatores de Probabilidade

A probabilidade de vitória é composta por uma taxa base mais 6 ajustes. Cada ajuste é independente antes do agrupamento por cluster.

Cluster Performance
1. Forma recente
delta = last5WR − older15WR
adj = clamp(delta × 0.4, −0.08, +0.08)
range: [−0.08, +0.08]
Compara vitórias das 5 partidas mais recentes vs. as 15 anteriores. Um delta de +20% gera +8% de ajuste (amplificação 0.4×).
Cluster Performance
2. Sequência (streak)
sign = +1 se win, −1 se loss
adj = sign × min(streakLen−1, 4) × 0.02
range: [−0.08, +0.08]
+2% por partida adicional na mesma sequência. Máximo em 5 partidas consecutivas (4 incrementos × 2% = 8%).
Cluster Skill
3. KDA médio
adj = (averageKDA − 2.0) × 0.02
range: não clamped (KDA implica)
KDA 2.0 é neutro (0). KDA 3.5 → +3%. KDA 1.0 → −2%. KDA de 8.0 → +12% (antes do desconto de cluster).
Cluster Skill
4. Rank (medalha)
medal = floor(rankTier / 10)
star = rankTier % 10
adj = (medal−4)×0.03 + (star−3)×0.005
veja tabela de ranks →
Medal 4 (Archon) é neutro. Cada medalha acima/abaixo de Archon vale ±3%. Cada estrela vale ±0.5%.
Cluster Economia
5. Tendência de GPM
delta = (avgGPM_last5 − avgGPM_prev5) / avgGPM_prev5
adj = clamp(delta × 0.1, −0.02, +0.02)
range: [−0.02, +0.02]
Mede a variação relativa do GPM médio das últimas 5 partidas vs. as 5 anteriores. Um aumento de 20% no GPM → +2%.
Cluster Economia
6. Tendência de XPM
delta = (avgXPM_last5 − avgXPM_prev5) / avgXPM_prev5
adj = clamp(delta × 0.1, −0.02, +0.02)
range: [−0.02, +0.02]
Idêntico ao GPM mas para XP por minuto. GPM e XPM são altamente correlacionados (ρ≈0.85) — XPM vale apenas 15% após desconto de cluster.

Clusters de Correlação

Se somarmos os 6 fatores diretamente, o sinal é inflado artificialmente porque os fatores são correlacionados. Um jogador em boa fase tem simultaneamente bom form, boa streak, bom KDA e bom GPM — somar tudo equivale a contar o mesmo sinal 4 vezes.

A solução: agrupar em 3 clusters e descontar os fatores secundários pela correlação intra-cluster. Clusters também têm diminishing returns entre si.

Desconto intra-cluster
// Cluster 1: Performance (corr form↔streak ≈ 0.65) performanceAdj = formAdj + streakAdj × 0.35 // streak vale 1 − 0.65 = 35% // Cluster 2: Skill (corr KDA↔rank ≈ 0.40) skillAdj = kdaAdj + rankAdj × 0.60 // rank vale 1 − 0.40 = 60% // Cluster 3: Economia (corr GPM↔XPM ≈ 0.85) economyAdj = gpmAdj + xpmAdj × 0.15 // XPM vale apenas 15%
Combinação cross-cluster (diminishing returns: 0.75²)
finalP = clamp( baseWinRate + performanceAdj // 100% do cluster de performance + skillAdj × 0.75 // skill desconta 25% cross-cluster + economyAdj × 0.5625, // economy desconta 0.75² = 43.75% 0.25, 0.75 // clamp final [25%, 75%] )
Por que 0.75 e 0.5625?
Os clusters de performance e economia têm correlação cruzada de aproximadamente 0.50 no Dota (jogadores em boa fase econômica tendem a vencer mais). O fator de desconto 0.75 = 1 − 0.25 aplica um desconto conservador. Para o terceiro cluster, o desconto compõe: 0.75² = 0.5625.

Fórmula Final Completa

// src/lib/odds.ts — calculateDynamicOdds() — versão comentada

// 1. Taxa base
const baseWinRate = matches.filter(isWin).length / matches.length;

// 2. Forma: last-5 vs partidas 6-20
const formAdjustment = Math.max(-0.08, Math.min(0.08, (last5WR - older15WR) * 0.4));

// 3. Streak: +2% por partida consecutiva, cap 4 incrementos (±8%)
const streakAdjustment = streakSign * Math.min(streakCount - 1, 4) * 0.02;

// 4. KDA: diferença de 2.0 × 2%
const kdaAdjustment = (stats.averageKDA - 2.0) * 0.02;

// 5. Rank: (medal−4)×3% + (star−3)×0.5%
const rankAdjustment = rankTierToMmrBonus(stats.rankTier);

// 6a. GPM: variação relativa last5 vs prev5, ampliada 0.1×, cap ±2%
const gpmDelta = prevGPM > 0 ? (lastGPM - prevGPM) / prevGPM : 0;
const gpmAdjustment = Math.max(-0.02, Math.min(0.02, gpmDelta * 0.1));

// 6b. XPM: idem
const xpmAdjustment = Math.max(-0.02, Math.min(0.02, xpmDelta * 0.1));

// 7. Clusters com desconto de correlação
const performanceAdj = formAdjustment + streakAdjustment * 0.35;
const skillAdj       = kdaAdjustment  + rankAdjustment  * 0.60;
const economyAdj     = gpmAdjustment  + xpmAdjustment   * 0.15;

// 8. Final com cross-cluster discount
const finalProbability = Math.max(0.25, Math.min(0.75,
  baseWinRate + performanceAdj + skillAdj * 0.75 + economyAdj * 0.5625
));

House Edge → Conversão em Odds

A probabilidade final é convertida para odds decimais pela função toOdds(p). A margem da casa (8%) é subtraída da odd justa. O teto de 1.80× aplica-se apenas em apostas simples — combos não têm teto.

toOdds(p) — src/lib/odds.ts:43
// Odds justa = 1/p // Com house edge: (1/p) × (1 − 0.08) = (1/p) × 0.92 toOdds(p) = Math.min(1.80, (1 / p) × 0.92) // Exemplos: // p = 0.50 → odds justa = 2.00 → com edge = 1.84 → mas > 1.80, então = 1.80× // p = 0.55 → odds justa = 1.82 → com edge = 1.67× // p = 0.60 → odds justa = 1.67 → com edge = 1.53× // p = 0.65 → odds justa = 1.54 → com edge = 1.41× // p = 0.70 → odds justa = 1.43 → com edge = 1.31× // p = 0.75 → odds justa = 1.33 → com edge = 1.23×

Impacto do teto 1.80×
Qualquer jogador com taxa de vitórias abaixo de ~54% recebe a odd máxima de 1.80× (em vez da odd calculada de 1.84–3.68×). Isso limita a exposição da casa a apostadores azarados que apostam na própria derrota e reduz o risco de grandes payouts em apostas simples.

Clamping ativo
Neste exemplo, a probabilidade calculada foi 0.753 — acima do máximo de 0.75. O clamp garante que nenhum jogador, por mais favorecido pelos fatores, receba odd abaixo de 1.23× para vitória (o que representaria um favorito muito extremo e impraticável de fazer apostas).

Apostas Combo — calculateComboOdds()

Uma aposta combo adiciona condições de performance além da vitória. Cada condição multiplica a probabilidade acumulada — tornando o combo mais difícil e a odd mais alta. Combos não têm teto de odd.

src/lib/bet-events.ts — calculateComboOdds()
combinedProb = winProbability × P(kills > threshold) // Poisson × P(assists > threshold) // Poisson × P(gpm > threshold) // Normal × P(xpm > threshold) // Normal rawOdds = (1 / combinedProb) × (1 - 0.08) finalOdds = isCombo ? rawOdds : Math.min(1.80, rawOdds)

Distribuições Estatísticas — calcOverProbability()

A função calcOverProbability(average, target, dist) calcula P(stat > target) dado que o jogador tem média histórica average. O modelo de distribuição varia por tipo de dado.

Poisson
KILLS e ASSISTS
// Contagem discreta (0, 1, 2, 3...) // Assimétrico à direita — Poisson(λ=avg) // Aproximação normal com correção de continuidade z = (avg − target − 0.5) / √avg P = normalCDF(z) // Exemplo: avg=7 kills, target=8 kills z = (7 − 8 − 0.5) / √7 z = −1.5 / 2.646 = −0.567 P = normalCDF(−0.567) ≈ 28.5% // Formulá linear anterior daria: // 0.5 + (7−8)/(7×2) = 0.43 (menos preciso)
Normal
GPM e XPM
// Dados contínuos com distribuição ~normal // CV empírico para economia no Dota: 0.22 // σ = μ × CV = avg × 0.22 z = (avg − target) / (avg × 0.22) P = normalCDF(z) // Exemplo: avg=500 GPM, target=550 GPM σ = 500 × 0.22 = 110 z = (500 − 550) / 110 = −0.455 P = normalCDF(−0.455) ≈ 32.5% // Fórmula linear anterior daria: // 0.5 + (500−550)/(500×2) = 0.45 (superestima)

Normal CDF — implementação

// src/lib/bet-events.ts — Abramowitz & Stegun 26.2.17
// Erro máximo < 7.5e-8 em todo o domínio real
function normalCDF(z: number): number {
  const a = [0.319381530, -0.356563782, 1.781477937, -1.821255978, 1.330274429];
  const t = 1 / (1 + 0.2316419 * Math.abs(z));
  // Avaliação de Horner — evita múltiplas potências
  const poly = t * (a[0] + t * (a[1] + t * (a[2] + t * (a[3] + t * a[4]))));
  const pdf  = Math.exp(-0.5 * z * z) / Math.sqrt(2 * Math.PI);
  const tail = pdf * poly;
  return z >= 0 ? 1 - tail : tail;
}
Por que correção de continuidade em Poisson?
Kills são inteiros (0, 1, 2...). P(kills > 7) = P(kills ≥ 8). Usando uma distribuição contínua para aproximar isso, o threshold 8 na discretização corresponde a 7.5 na contínua. A correção −0.5 no numerador do z-score acomoda isso. Sem ela, a probabilidade seria sistematicamente subestimada no threshold exato.

Padrões de Banco de Dados

Débito atômico (anti-race-condition)

// updateMany com condição WHERE balance >= amount
// Se 0 linhas afetadas → saldo insuficiente (detectado sem race condition)
const updated = await tx.wallet.updateMany({
  where: { userId, balance: { gte: amount } },
  data:  { balance: { decrement: amount } },
});
if (updated.count === 0) throw new Error("INSUFFICIENT_BALANCE");

Bônus idempotente (sem race condition em depósitos concorrentes)

// depositBonusClaimed: false → claimed atomicamente no UPDATE
// Segundo request paralelo encontra 0 linhas e não ganha bônus
const claimed = await tx.wallet.updateMany({
  where: { userId, depositBonusClaimed: false },
  data:  { depositBonusClaimed: true },
});
if (claimed.count > 0) { /* aplicar bônus */ }
Regras de transação
Qualquer operação que envolva débito + crédito + log deve estar dentro de prisma.$transaction(). Se qualquer operação falhar, tudo é revertido. Nunca faça débito fora de uma transação.
